> **状态**：活文档，随产品演进持续更新。
> **决策与理由**写在本文对应章节；原始调研依据见 [`research/`](research/)（带日期快照，不回改）。

## 1. 一句话定位

**《通识局》是一款 12 域通识知识闯关游戏**：每天用 5 道题检验你在「游戏 / 动漫 / 科技 / 编程 / 生活 / 历史 / 汽车 / 手机 / 电影 / 科学 / 语文 / 地理」上的常识库存，
同时提供一个**同步抢答**的好友对战模式，把「你到底知道多少」变成可以当场比出来的对抗。

**它不是**又一个「无限答题流」的 App。区别在于五件事：

1. **每天的题全网一样** —— 同样的日期、同样的领域组合，题目与顺序在全世界完全一致，结果天然可比、可分享；
2. **题是有解析的知识密度载体**，不是纯娱乐的脑筋急转弯；
3. **错题有记忆** —— 答错的题进入间隔重复队列，连续答对两次才算「毕业」；到期题不会主动塞回当日题集（见 §5.3 与 GAME-RULES §6.1）；
4. **你有一个零成本的对手** —— **过去的自己**。没有账号、没有排行榜、不需要服务端，照样有"我今天比昨天强"的实感；
5. **同一个码，同一份题** —— 两个人输入同一个 PK 码，各自本地跑同一份纯函数，拿到**完全相同**的 5 道题。

## 2. 目标用户

| 人群 | 场景 | 核心诉求 |
|---|---|---|
| **通勤碎片玩家** | 每天 3–5 分钟，地铁上打开 | 不用想「玩什么」，打开就有题；连答天数不能断 |
| **知识型社交玩家** | 午休跟同事开一局 | 同一份题、同时开抢，输赢当场分晓 |
| **领域爱好者** | 只想玩游戏 / 动漫 / 编程 | 选自己的本命领域，别被其他领域的题打扰 |
| **想被拓宽的人** | 知道自己知识面窄 | 每天被两个「意料之外」的领域推着走 |
| **内容创作者** | 想发成绩图 | 一键生成 1200×630 成绩卡，带星级与连击数 |

## 4. 亮点玩法

> 这些机制是本产品的**新鲜感来源**。它们共同满足三条硬约束：
> **① 零服务端成本 ② 不破坏每日挑战的无状态架构 ③ 每天给玩家一个"再来一次"的理由。**

### 4.1 影子对手 —— 「和昨天的自己同场竞速」

#### 问题
竞品普遍用**排行榜**做长期钩子（Wordle 分享、Duolingo 联赛、Kahoot）。
但排行榜需要服务端、需要账号、需要反作弊。本项目**没有账号体系**（见
[`ARCHITECTURE.md`](ARCHITECTURE.md) §9），
排行榜既做不出来也不该做。

#### 机制
每日挑战是**无状态**的 —— 同一天同领域组合，全网拿到同一份题。
正因为无状态，我们可以做一个**零服务端成本**的对手：**你过去的自己**。

- 系统按**领域集合**记住你过去的最好成绩（影子），存在 localStorage；
- 答题过程中，影子的成绩以一条**金色目标线**画在进度条上；
- 结算时给出结论：超过了 / 追平 / 差多少。

#### 规则

影子归属、取最高分、`near` 阈值与更新顺序见 [`GAME-RULES.md`](GAME-RULES.md) §4。

#### 为什么不做成"两个小人赛跑"
我们**没有**影子每一题的确切用时（本地只存了总成绩）。
硬造一条"影子在第 2 题用了 8 秒"的曲线就是**编数据**。
所以只画一条诚实的线：影子的**最终成绩**。它不是假赛跑，是一条**目标线**：
"你需要在剩下两题里越过这条线。"

#### 验收标准
- [ ] 首次挑战某组领域 → 结算页显示「第一次挑战 —— 今天的成绩就是明天的影子」
- [ ] 第二次挑战且分数更高 → 显示「超过过去的自己 N 分」
- [ ] 分数低于影子 → 显示差距，且差距 ≤10% 时文案为「差 N 分就追平影子」
- [ ] 领域集合不同 → 影子互不干扰
- [ ] 全部数据在 localStorage，**无任何服务端调用**

### 4.2 通识段位 —— 把「每天玩一下」变成看得见的成长线

#### 问题
每日挑战的反馈是**单局**的：今天多少分、几颗星。
缺一个**跨天累积**的成长刻度，玩家感知不到"我比上个月强"。

#### 机制

六个段位，由**本地生涯累计数据**算出。门槛、通识值公式与段内进度语义见
[`GAME-RULES.md`](GAME-RULES.md) §5。

成长节奏：前期约 2 天入门，约 3 个月到顶，越往后越慢。

#### 验收标准
- [ ] 首页与结算页都展示当前段位、描述、段内进度条
- [ ] 段位由**生涯累计**算出，不受"最近 30 场"历史窗口影响
- [ ] 数据全在 localStorage，无服务端调用
- [ ] 段位门槛单调递增，进度恒在 [0,1]

### 4.3 盲盒轮转 —— 「1 个本命 + 2 个每日盲盒」

#### 问题
固定本命领域有好处（稳定），也有坏处：玩家会把自己锁进舒适区。
选游戏和动漫的人，半年后只会这两块 —— 而"通识"这个词也就名不副实了。

#### 机制
玩家只固定 **1 个本命**（真正想长期深入的领域），另外 **2 个由日期种子决定**，当天全网一致，**明天换新**。

- 盲盒领域**与用户无关**：同一天、同一本命 → 同一批盲盒领域；
- 盲盒池剔除了本命，不会出现"本命 + 盲盒里又是本命"；
- 完全**纯函数**，不需要任何服务端状态。

公式与三种模式（本命 / 盲盒轮转 / 随缘开局）的档案写回规则见
[`GAME-RULES.md`](GAME-RULES.md) §1.3、§2.2。

#### 验收标准
- [ ] 选域页可切换三种模式，模式说明可见
- [ ] 盲盒模式下最多只能选 1 个本命
- [ ] 同一天同一本命 → 盲盒领域完全一致
- [ ] 跨日期 → 盲盒领域会轮换
- [ ] 「随缘开局」**不写回档案** —— 写回会导致第二天起不再轮换（这是修掉的一个老 bug）

### 4.4 同题 PK —— 「同一个码，同一份题」

两个人输入同一个 PK 码，各自本地跑同一份纯函数，拿到完全相同的 5 道题；
成绩卡带 PK 码与 5 格方块，逐格对账。完整玩法与边界见 §5.4，公式见
[`GAME-RULES.md`](GAME-RULES.md) §11。

## 5. 四条产品线

### 5.1 每日挑战（Daily Challenge）—— 无状态、确定性、跨天 streak

**核心机制**：

题集由「日期 + 领域集合」的纯函数确定，`dateKey` 按 **Asia/Shanghai** 计算（`YYYY-MM-DD`），跨零点自动换题。
因此：

- 同一天 + 同一组领域 → **全网同一份题**（同题同序同难度曲线）；
- 领域按**集合**处理，选同一组领域的两个人，哪怕点选顺序不同，拿到的题也完全一致；
- 每日挑战**不需要任何服务端状态** → 可以部署到任意 Serverless，随时扩容。

公式、退化行为与难度曲线见 [`GAME-RULES.md`](GAME-RULES.md) §1–2。

**一轮 5 题**，难度曲线 `1 → 1 → 2 → 2 → 3`，末位为**彩蛋题**（强制换域，制造节奏变化）。

计分、限时、星级与秒答加成见 [`GAME-RULES.md`](GAME-RULES.md) §3。

**跨天 streak**：每天完成一次即 +1，**断签归 1**（不是归零 —— 断签只清连续天数，不清历史最高），
历史最长单独记录（存 localStorage）。详见 [`GAME-RULES.md`](GAME-RULES.md) §7。

**知识链**（连击的可视化）：答题过程中顶部有一条分段轨道，
每答对一题点亮一格（颜色 = 该题所属领域），让"跨域连击"从数字变成看得见的轨道。

### 5.2 同步抢答 duel —— 服务端权威计时 + SSE 实时

#### 为什么是同步抢答，而不是平行竞速

- 平行竞速（两人各答各的题、比速度）对**知识量**的考察弱、对**反应速度**的考察强，长期缺乏话题性；
- 同步抢答天然带「敢不敢早按」的博弈张力，与本项目的**知识密度**定位互补；
- 同步抢答对题目的**确定性**要求更高（双方必须看到同一题面），这正好可以用每日挑战那套纯函数种子机制解决。

**玩法**：双方看到**同一道题、同一倒计时**。每人每题**只有一次提交机会**：

- 答对且**先于对手** → 立即锁定并结算本回合，独占该题分值，对手该题 0 分；
- 答错 → 该题 0 分、连击**立即**归零，但**回合不结束** —— 对手在截止前答对照样拿走分值；
- **双方都答错** → 第二次提交的那一刻立即结算本回合（0 比 0），不空等剩余读秒；
- 没人答、或只有一人答且答错 → 到 `deadlineAt` 时本回合无人得分。

> **为什么「双方都答错」要提前结算**：「答错后回合不结束」的前提是**对手还有机会**。
> 两人都提交过之后，每人每题只有一次机会，剩下的读秒不可能再改变任何结果 ——
> 空等最长 30 秒只会把对局拖成死寂（实测：公网隧道上双方都错要干等一整轮限时才切题）。
>
> **对手掉线仍然照等**：提前结算的判据只看「有没有作答」，不看在线状态。
> 掉线的一方仍然握着这一题的机会；否则「切出去不答」就成了战术。

**跨域连击**：跨域抢先答对 +1，同域不变，答错/超时归零，**对手抢先答对不算你失误**。
完整表格与倍率曲线见 [`GAME-RULES.md`](GAME-RULES.md) §3.4–3.5。

**服务端权威**：计时、答案判定、回合推进、胜负判定全部在服务端；
客户端只提交答案，用时由服务端计算。接口细节见 [`API.md`](API.md) §2.7。

**结算落本地档案**：只写本人实际作答过的回合（`history` + 熟练度 + 错题本），
不写 streak / 段位 / 影子；同一场用 `matchId` 去重。完整口径见
[`GAME-RULES.md`](GAME-RULES.md) §11.3。

**实时通道**：SSE（`/api/rooms/[code]/stream`）。心跳、主动轮换、僵尸回收的参数与原因见
[`ARCHITECTURE.md`](ARCHITECTURE.md) §4；事件与错误见 [`API.md`](API.md) §3。

**相位机**：`lobby → countdown → question → feedback → finished`，
推进与重连规则见 [`ARCHITECTURE.md`](ARCHITECTURE.md) §3。

**凭证纪律**：`playerId` 只出现在创建/加入房间的私有响应；快照与广播对外一律用 `slot`；
`RoomState.questions` 只存元数据。红线见 [`../AGENTS.md`](../AGENTS.md) §2.3，接口细节见 [`API.md`](API.md) §0.3。

### 5.3 错题重逢 · 知识星图 —— 长期留存

**错题间隔重逢**（SM-2 简化版）：间隔序列、毕业条件与难度因子变化见
[`GAME-RULES.md`](GAME-RULES.md) §6。

**到期练习流**（`/wrong/practice`）：`/wrong` 的「开始复习 N 题」只对到期题开放；
独立练习无倒计时、不计分、不写战绩 / streak / 段位 / 熟练度，只推进错题间隔。
完整口径见 [`GAME-RULES.md`](GAME-RULES.md) §6.1。

**知识星图**（`/map`）：12 域的掌握分布雷达图，一眼看出「我在哪一块有洞」。

**战绩**（`/history`）：最近 30 场记录 + 分数趋势。

**全部本地存储**：档案、错题本、熟练度、战绩、streak、影子、段位都在 localStorage，不做账号体系。

### 5.4 同题 PK —— 「同一个码，同一份题」

#### 问题
「全网同题」是本项目**最独特的技术资产**，但此前只被用来做排行榜的底座 ——
而排行榜需要服务端、账号与反作弊，本项目一个都没有。这块资产在**浪费**。

#### 机制
两个人约定一个 4–6 位的 **PK 码**（今天还有一个全网一致的「今日推荐码」）。
PK 码、种子、领域与题集公式见 [`GAME-RULES.md`](GAME-RULES.md) §11.1。

因为 `buildDailySet` **本来就支持显式 seed**（duel 已在用），
所以两个人**各自本地跑一遍**，得到**完全相同**的 5 道题、相同顺序、相同难度曲线。

- 两人各自作答、各自计时、各自算分；
- 成绩卡带上 **PK 码** 与 **5 格题目方块**（每格一个领域色），逐格对账；
- **零服务端**：不需要撮合、不需要存题、不需要比对。

#### 诚实的边界
| 有 | 没有 |
|---|---|
| 题目完全一致 | 实时同步（不是同时开抢，是"同题、各自跑、最后比"） |
| 可用成绩卡逐题对账 | 自动判胜（要靠成绩卡线下对照） |
| 换设备也能玩（码一样题就一样） | 换设备共享进度（没有账号体系） |

#### 验收标准
- [ ] 两人输入同一个码 → 领域集合、题目顺序、答案完全一致
- [ ] 换一个码 → 题目不同
- [ ] 今日推荐码全网一致
- [ ] 成绩卡包含 PK 码与 5 格方块
- [ ] 全程无任何服务端调用

## 7. AI 出题（特色但受限）

**定位**：内容补充工具，**不是**每日挑战的题源。

- 支持 OpenAI 兼容 API 与 Ollama；未配置 provider 时接口返回 503，主链路不受影响；
- 配置键见 [`.env.example`](../.env.example)，接口契约见 [`API.md`](API.md) §4；
- 生成结果只进**待审池**（`status: "pending"`，服务端不落盘），
  10 步校验链与人工入库流程见 [`CONTENT.md`](CONTENT.md) §8。

**变体模式**：入参带 `variantOf`（原题 `questionId` / `stem` / `answer`）时改走变体 prompt，
生成的题 `variantOf` 指向原题 id。**目前只有接口能力** ——
`variantOf` 字段与「变体优先出题」的策略**都还没有客户端入口**（错题本页不调用该接口）。

## 11. 后续路线

### 11.1 明确不做（已裁定，不再反复讨论）

| 议题 | 裁定 | 理由 |
|---|---|---|
| **连胜玩法**（连续打卡里程碑、护盾、连击式奖励） | 先不引入 | NYT Mini 官方明示**不做连胜**（每日同题本身就够）；Duolingo 靠连胜做成规模，但那是**损失厌恶**驱动的 —— 断签的心理痛苦约为收益快感的两倍，会制造"断了就全没了"的焦虑，与本项目的知识密度定位不匹配。已有的**跨天 streak** 只做最小记录（断签归 1），不加任何惩罚机制 |
| **服务端排行榜** | 不做 | §4.1 已论证：排行榜需要服务端 + 账号 + 反作弊，本项目三者都没有，硬做就是拿"全网同题"这块资产去换一个做不出来的功能。它想满足的**比较需求**已由「同题 PK」（零服务端、成绩卡逐格对账）与「影子对手」（比自己昨天）承担。要重启这件事，前提是先决定引入账号体系 —— 那是另一个产品 |
| **抄 QuizUp 的重运营结构**（匹配撮合 / 全球榜单 / 赛季） | 不做 | QuizUp 8000 万注册、日均 40 分钟、10 亿+ 对局，仍于 2021 年关服。**重运营结构对一个无账号体系的独立产品是负资产**。本项目只抄 Wordle 的**传播结构**（零服务端、纯文本、全网同题），那才是唯一的结构性优势 |

> 依据：[`docs/research/2026-10-20-竞品与设计参考.md`](research/2026-10-20-竞品与设计参考.md) §8。
> 替代性留存锚点已由「影子对手 + 通识段位 + 盲盒轮转 + 同题 PK」提供（见 §4）。

> 排序判据只有一个：**这个缺口会不会让产品本身出错或骗人**。
> 演示效果好看不等于优先级高。每条写清"现在不做会怎样"，方便下次直接判。
>
> 原本的两条 P0 均已完成：**内容安全卡口**（§10 #14）与**客户端冒烟自动化**（§10 #15）。
> 两条 P1 也已完成（2026-10-21）：**duel 结算落本地档案**（§10 #16）与
> **到期错题的练习出口**（§10 #17）。已完成的项不留在这里。

**P2 · 内容与运营，不做不影响正确性**

  需要审核界面 + 入库流水线，否则这条管线只能靠人手工搬。
- **题库深度**：每域 40 → 60 题，把单域重复率压下去（引擎已兜底"允许重复"而非空面，所以是质量问题不是故障）。
  配套工作量在内容侧，不在代码侧。

**P3 · 锦上添花，随时可推**

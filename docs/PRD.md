## 1. 一句话定位

**《通识局》是一款 12 域通识知识闯关游戏**：每天用 5 道题检验你在「游戏 / 动漫 / 科技 / 编程 / 生活 / 历史 / 汽车 / 手机 / 电影 / 科学 / 语文 / 地理」上的常识库存，
同时提供一个**同步抢答**的好友对战模式，把「你到底知道多少」变成可以当场比出来的对抗。

**它不是**又一个「无限答题流」的 App。区别在于五件事：

1. **每天的题全网一样** —— 同样的日期、同样的领域组合，题目与顺序在全世界完全一致，结果天然可比、可分享；
2. **题是有解析的知识密度载体**，不是纯娱乐的脑筋急转弯；
3. **错题有记忆** —— 答错的题按 `1/3/7/15/30` 天进入间隔计时，之后每次再遇到同一道题都按这条序列推进，连续答对两次才算「毕业」（当前不主动把到期题塞回当日题集，见 §5.3 与 GAME-RULES §6.1）；
4. **你有一个零成本的对手** —— **过去的自己**。没有账号、没有排行榜、不需要服务端，照样有"我今天比昨天强"的实感；
5. **同一个码，同一份题** —— 两个人输入同一个 PK 码，各自本地跑同一份纯函数，拿到**完全相同**的 5 道题。

| 人群 | 场景 | 核心诉求 |

| **通勤碎片玩家** | 每天 3–5 分钟，地铁上打开 | 不用想「玩什么」，打开就有题；连答天数不能断 |

| **内容创作者** | 想发成绩图 | 一键生成 1200×630 成绩卡，带星级与连击数 |

## 4. 三个亮点玩法

> 这三个机制是本产品的**新鲜感来源**。它们共同满足三条硬约束：
> **① 零服务端成本 ② 不破坏每日挑战的无状态架构 ③ 每天给玩家一个"再来一次"的理由。**

### 4.1 影子对手 —— 「和昨天的自己同场竞速」

#### 问题
竞品普遍用**排行榜**做长期钩子（Wordle 分享、Duolingo 联赛、Kahoot）。
但排行榜需要服务端、需要账号、需要反作弊。本项目**没有账号体系**（见 §9 已知限制），
排行榜既做不出来也不该做。

#### 机制
每日挑战是**无状态**的 —— 同一天同领域组合，全网拿到同一份题。
正因为无状态，我们可以做一个**零服务端成本**的对手：**你过去的自己**。

- 系统按**领域集合**记住你过去的最好成绩（影子），存在 localStorage；
- 答题过程中，影子的成绩以一条**金色目标线**画在进度条上；
- 结算时给出结论：超过了 / 追平 / 差多少。

#### 规则

| 项 | 规则 |
|---|---|
| 影子归属 | 按**领域集合**（规范序）分组 —— 选同一组领域才是同一个对手 |
| 影子成绩 | 该组领域下的**历史最高总分**（同分则取更快的那次） |
| 判定 | `delta = 本次得分 - 影子得分`；`>0` 超越 / `=0` 追平 / `<0` 落后 |
| 「差一点」 | 差距 ≤ 影子分 × 10% 记为 `near`（文案更友好） |
| 更新时机 | 结算时刷新；**对比用的是本局开始前的影子**（先算结论再更新，否则等于自己跟自己比） |

#### 为什么不做成"两个小人赛跑"
我们**没有**影子每一题的确切用时（本地只存了总成绩）。
硬造一条"影子在第 2 题用了 8 秒"的曲线就是**编数据**。
所以只画一条诚实的线：影子的**最终成绩**。它不是假赛跑，是一条**目标线**：
"你需要在剩下两题里越过这条线。"

#### 验收标准
- [ ] 首次挑战某组领域 → 结算页显示「第一次挑战 —— 今天的成绩就是明天的影子」
- [ ] 第二次挑战且分数更高 → 显示「超过过去的自己 N 分」
- [ ] 分数低于影子 → 显示差距，且差距 ≤10% 时文案为「差 N 分就追平影子」
- [ ] 领域集合不同 → 影子互不干扰
- [ ] 全部数据在 localStorage，**无任何服务端调用**

### 4.2 通识段位 —— 把「每天玩一下」变成看得见的成长线

#### 问题
每日挑战的反馈是**单局**的：今天多少分、几颗星。
缺一个**跨天累积**的成长刻度，玩家感知不到"我比上个月强"。

#### 机制
六个段位，由**本地生涯累计数据**算出：

```
通识值 = 答对题数×3 + 完成局数×4 + 星级总数×6 + 触及知识点数×2 + 最高连击×5 + 最长连续天数×2
```

| 段位 | 通识值门槛 | 描述 | 大致耗时 |
|---|---|---|---|
| 见习 | 0 | 刚进门，路还没认熟 | — |
| 入门 | 150 | 开始上道了 | ≈ 2 天 |
| 通识 | 600 | 像个通识玩家了 | ≈ 8 天 |
| 博闻 | 1500 | 朋友愿意跟你聊 | ≈ 3 周 |
| 渊博 | 3200 | 话题覆盖半个互联网 | ≈ 1.5 月 |
| 睿哲 | 6000 | 身边人的知识百科 | ≈ 3 月 |

**进度条是"段内进度"**：晋级瞬间归零重来，而不是累计百分比 —— 每一段都要重新爬一遍，才有仪式感。

#### 验收标准
- [ ] 首页与结算页都展示当前段位、描述、段内进度条
- [ ] 段位由**生涯累计**算出，不受"最近 30 场"历史窗口影响
- [ ] 数据全在 localStorage，无服务端调用
- [ ] 段位门槛单调递增，进度恒在 [0,1]

### 4.3 盲盒轮转 —— 「1 个本命 + 2 个每日盲盒」

#### 问题
固定本命领域有好处（稳定），也有坏处：玩家会把自己锁进舒适区。
选游戏和动漫的人，半年后只会这两块 —— 而"通识"这个词也就名不副实了。

#### 机制
玩家只固定 **1 个本命**（真正想长期深入的领域），另外 **2 个由日期种子决定**，当天全网一致，**明天换新**。

```
盲盒领域 = pickDomainsBySeed(hashSeed("blindbox:" + dateKey), 候选池 \ {本命}, 2)
实际领域 = 本命 ∪ 盲盒领域
```

- 盲盒领域**与用户无关**：同一天，同一份候选池 → 同一批盲盒领域（"全网同题"在盲盒模式下依然成立）；
- 盲盒池剔除了本命，不会出现"本命 + 盲盒里又是本命"；
- 完全**纯函数**，不需要任何服务端状态。

#### 三种领域模式

| 模式 | 领域来源 | 适合谁 |
|---|---|---|
| **本命模式** | 玩家选定的 1–3 个，固定 | 领域爱好者 |
| **盲盒轮转** | 1 个本命 + 2 个每日盲盒 | 想被拓宽的人 |
| **随缘开局** | 完全按日期种子取 3 个，每天换 | 不想做选择的人 |

#### 验收标准
- [ ] 选域页可切换三种模式，模式说明可见
- [ ] 盲盒模式下最多只能选 1 个本命
- [ ] 同一天同一本命 → 盲盒领域完全一致
- [ ] 跨日期 → 盲盒领域会轮换
- [ ] 「随缘开局」**不写回档案** —— 写回会导致第二天起不再轮换（这是修掉的一个老 bug）

## 5. 四条产品线

### 5.1 每日挑战（Daily Challenge）—— 无状态、确定性、跨天 streak

**核心机制**：

```
题集 = f(daySeed, domains, count)
daySeed = hashSeed("daily:" + dateKey + ":" + canonicalDomains(domains).join(","))
```

`dateKey` 按 **Asia/Shanghai** 计算（`YYYY-MM-DD`），跨零点自动换题。
客户端与服务端跑**同一份** `lib/engine/daily.ts`，因此：

- 同一天 + 同一组领域 → **全网同一份题**（同题同序同难度曲线）；
- 领域按**集合**处理（`canonicalDomains()` 先排序）—— 选同一组领域的两个人，
  哪怕点选顺序不同，拿到的题也完全一致；
- 每日挑战**不需要任何服务端状态** → 可以部署到任意 Serverless，随时扩容。

**一轮 5 题**，难度曲线 `1 → 1 → 2 → 2 → 3`，末位为**彩蛋题**（强制换域，制造节奏变化）。

**计分公式**：

```
base   = { 难度1: 10, 难度2: 20, 难度3: 30 }
speed  = clamp(1 - elapsed / limit, 0, 1) * 0.5 + 0.5     // 0.5 ~ 1.0
blitz  = elapsed <= limit / 3 ? 1.2 : 1.0                  // 秒答加成
points = round(base * speed * blitz * comboMultiplier)
```

限时随难度递减：难度 1 = 30s，难度 2 = 25s，难度 3 = 20s。

**星级**：≥60% 满分 → ★★★；≥35% → ★★；其余 ★。

**跨天 streak**：每天完成一次即 +1，**断签归 1**（不是归零 —— 断签只清连续天数，不清历史最高），
历史最长单独记录（存 localStorage）。详见 [`GAME-RULES.md`](GAME-RULES.md) §7。

**知识链**（连击的可视化）：答题过程中顶部有一条分段轨道，
每答对一题点亮一格（颜色 = 该题所属领域），让"跨域连击"从数字变成看得见的轨道。

### 5.2 同步抢答 duel —— 服务端权威计时 + SSE 实时

#### 为什么是同步抢答，而不是平行竞速

- 平行竞速（两人各答各的题、比速度）对**知识量**的考察弱、对**反应速度**的考察强，长期缺乏话题性；
- 同步抢答天然带「敢不敢早按」的博弈张力，与本项目的**知识密度**定位互补；
- 同步抢答对题目的**确定性**要求更高（双方必须看到同一题面），这正好可以用每日挑战那套纯函数种子机制解决。

**玩法**：双方看到**同一道题、同一倒计时**。每人每题**只有一次提交机会**：

- 答对且**先于对手** → 立即锁定并结算本回合，独占该题分值，对手该题 0 分；
- 答错 → 该题 0 分、连击**立即**归零，但**回合不结束** —— 对手在截止前答对照样拿走分值；
- 双方都答错或都没答 → 到 `deadlineAt` 时本回合无人得分。

**跨域连击（纯正向激励）**：

| 情况 | 连击变化 |
|---|---|
| 跨域抢先答对 | **+1** |
| 同域抢先答对 | 不变（不奖不罚） |
| 答错 | **归零** |
| 超时未答 | **归零** |
| **对手抢先答对** | **不变**（这不算你失误） |

倍率曲线：`0-1 → ×1.0`，`2-3 → ×1.05`，`4-5 → ×1.1`，`6+ → ×1.2`（封顶，避免滚雪球）。

**服务端权威**：计时、答案判定、回合推进、胜负判定**全部在服务端**。
客户端只提交答案，从不上报用时（`elapsed` 由服务端按收到时刻计算），
提交体中的未知字段会被 Zod 剥离。

**实时通道**：SSE（`/api/rooms/[code]/stream`）。

| 机制 | 参数 | 原因 |
|---|---|---|
| 心跳 | 25s | 保活中间代理，顺带在写失败时兜底清理 |
| 主动轮换 | 100s | 在平台 120s 硬杀前优雅关闭，把「平台硬杀」变成「清理必然执行」 |
| 僵尸回收 | 130s 判超龄 | 平台掐断后 `cancel()` 不保证触发，残留会占满配额导致「重连永远 429」 |

**相位机**：`lobby → countdown → question → feedback → (下一回合) → finished`。
推进采用「**惰性 + 定时器**」双保险 —— `syncRoomPhase()` 在读快照 / 提交答案 / 定时器回调三处调用，
Serverless 定时器丢失也能靠下一次调用收敛。

**凭证纪律**（安全红线）：

- `playerId` 只在**创建/加入房间的私有响应**里下发给本人；
- 快照与广播中 `players[].id` **一律脱敏**，对外一律用 **slot 索引**（`0` = 房主，`1` = 访客）；
- `RoomState.questions` **只存元数据**，答案与解析在结算时才下发。

### 5.3 错题重逢 · 知识星图 —— 长期留存

**错题间隔重逢**（SM-2 简化版）：

- 间隔序列：`1 → 3 → 7 → 15 → 30` 天；
- 答错 → 连击归零、间隔重置到第 1 级、难度因子下调；
- 答对 → 连击 +1、间隔推进到下一级；
- **连续答对 2 次 → 毕业**（从错题队列移出）。

> **投递现状（不要写成"会自动回来"）**：当日题集是 `f(日期, 领域集合)` 的纯函数，
> 入参里没有错题队列 —— 这是每日挑战无状态红线的一部分，不能为了"回来"而破坏它。
> 所以一道错题的「重逢」= 之后某天**恰好又抽到同一道题**；`/wrong` 只读，没有重做入口。
> 补一条**独立的到期练习流**（不进当日题集、不影响全网同题）已列入 §11.2。
> 完整口径见 [`GAME-RULES.md`](GAME-RULES.md) §6.1。

**知识星图**（`/map`）：12 域的掌握分布雷达图，一眼看出「我在哪一块有洞」。

**战绩**（`/history`）：最近 30 场记录 + 分数趋势。

**全部本地存储**：档案、错题本、熟练度、战绩、streak、影子、段位都在 localStorage，不做账号体系。

### 5.4 同题 PK —— 「同一个码，同一份题」

#### 问题
「全网同题」是本项目**最独特的技术资产**，但此前只被用来做排行榜的底座 ——
而排行榜需要服务端、账号与反作弊，本项目一个都没有。这块资产在**浪费**。

#### 机制
两个人约定一个 4–6 位的 **PK 码**（今天还有一个全网一致的「今日推荐码」）：

```
pkSeed(dateKey, code)    = hashSeed("pk:" + dateKey + ":" + code)
pkDomains(dateKey, code) = pickDomainsBySeed(hashSeed("pk-domains:" + dateKey + ":" + code), 池, 3)
题集 = buildDailySet({ dateKey, domains, pool, seed })
```

因为 `buildDailySet` **本来就支持显式 seed**（duel 已在用），
所以两个人**各自本地跑一遍**，得到**完全相同**的 5 道题、相同顺序、相同难度曲线。

- 两人各自作答、各自计时、各自算分；
- 成绩卡带上 **PK 码** 与 **5 格题目方块**（每格一个领域色），逐格对账；
- **零服务端**：不需要撮合、不需要存题、不需要比对。

#### 诚实的边界
| 有 | 没有 |
|---|---|
| 题目完全一致 | 实时同步（不是同时开抢，是"同题、各自跑、最后比"） |
| 可用成绩卡逐题对账 | 自动判胜（要靠成绩卡线下对照） |
| 换设备也能玩（码一样题就一样） | 换设备共享进度（没有账号体系） |

#### 验收标准
- [ ] 两人输入同一个码 → 领域集合、题目顺序、答案完全一致
- [ ] 换一个码 → 题目不同
- [ ] 今日推荐码全网一致
- [ ] 成绩卡包含 PK 码与 5 格方块
- [ ] 全程无任何服务端调用

## 7. AI 出题（特色但受限）

**定位**：内容补充工具，**不是**每日挑战的题源。

- 支持 OpenAI 兼容 API（`AI_API_BASE` / `AI_API_KEY` / `AI_MODEL`）与 Ollama；
- 未配置 provider 时接口直接返回 503，主链路完全不受影响；
- 生成结果过 **10 步校验链**：JSON 可解析 → 字段齐全 → domain/topic 命中白名单 → 难度合法 →
  答案命中选项 → 无歧义句式 → 解析长度达标 → 指纹去重 → 近似去重（Jaccard > 0.85）→ 敏感词过滤；
- 通过校验的题目只进**待审池**（响应里的 `status: 'pending'`），人工抽检后才转正式题库；
  **服务端不落盘** —— 待审池目前只是响应标记，运营界面尚未做（见 §11.2）；
- **AI 题永不参与每日挑战** —— 每日挑战必须可复现、可排行。

**变体模式**：入参带 `variantOf`（原题 `questionId` / `stem` / `answer`）时改走变体 prompt，
生成的题 `variantOf` 指向原题 id。**目前只有接口能力** ——
`variantOf` 字段与「变体优先出题」的策略**都还没有客户端入口**（错题本页不调用该接口）。

| 轨道 | 承载 | 平台 | 状态性 |
|---|---|---|---|

## 9. 技术约束（硬性）

- 依赖仅限 `zod` / `nanoid` / `lucide-react`（框架自带的 `react` / `next` 除外）；
  状态用 React + localStorage，**不引状态库**；
- **PRNG、题库、计分、日期全部自实现**，不引入游戏/随机/日期库；
- 答案以**选项文本**存储而非 A/B/C/D 字母（客户端可能对选项排序，字母会失效）；
- 多选题答案入库时按**原始字符串字典序**排序，比较时按**归一化后**排序（两套顺序分开）；
- `edgeone.json` 的 `nodeFunctionsConfig.maxDuration = 120` **必须保留**，CI 会检查；
- 测试 glob 用**单星** `__tests__/*.test.ts`（双星在 Linux CI 会假绿灯）。

## 11. 后续路线

### 11.1 明确不做（已裁定，不再反复讨论）

| 议题 | 裁定 | 理由 |
|---|---|---|
| **连胜玩法**（连续打卡里程碑、护盾、连击式奖励） | 先不引入 | NYT Mini 官方明示**不做连胜**（每日同题本身就够）；Duolingo 靠连胜做成规模，但那是**损失厌恶**驱动的 —— 断签的心理痛苦约为收益快感的两倍，会制造"断了就全没了"的焦虑，与本项目的知识密度定位不匹配。已有的**跨天 streak** 只做最小记录（断签归 1），不加任何惩罚机制 |
| **服务端排行榜** | 不做 | §4.1 已论证：排行榜需要服务端 + 账号 + 反作弊，本项目三者都没有，硬做就是拿"全网同题"这块资产去换一个做不出来的功能。它想满足的**比较需求**已由「同题 PK」（零服务端、成绩卡逐格对账）与「影子对手」（比自己昨天）承担。要重启这件事，前提是先决定引入账号体系 —— 那是另一个产品 |
| **抄 QuizUp 的重运营结构**（匹配撮合 / 全球榜单 / 赛季） | 不做 | QuizUp 8000 万注册、日均 40 分钟、10 亿+ 对局，仍于 2021 年关服。**重运营结构对一个无账号体系的独立产品是负资产**。本项目只抄 Wordle 的**传播结构**（零服务端、纯文本、全网同题），那才是唯一的结构性优势 |

> 依据：[`docs/research/2026-10-20-竞品与设计参考.md`](research/2026-10-20-竞品与设计参考.md) §8。
> 替代性留存锚点已由「影子对手 + 通识段位 + 盲盒轮转 + 同题 PK」提供（见 §4）。

### 11.2 待做（按"值不值得现在动手"分层）

> 排序判据只有一个：**这个缺口会不会让产品本身出错或骗人**。
> 演示效果好看不等于优先级高。每条写清"现在不做会怎样"，方便下次直接判。
>
> 原本的两条 P0（人工题库内容安全卡口、客户端冒烟自动化进 CI）**已完成**，
> 见 §10 成功标准第 14 / 15 项 —— 已完成的项不留在这里。

**P1 · 让已上线的功能名副其实**

- **duel 结算落本地档案**：duel 目前**不写任何本地档案**（熟练度 / 错题本 / 战绩 / streak / 段位全不记），
  `HistoryEntry.mode: "duel"` 与 `roomCode` 是**没有写入方的预留字段**。
  建议与 PK 同列：写 history + 熟练度 + 错题本，**不计** streak 与段位（防刷）。
  不做就一直背着"对战有战绩"的错觉。口径见 [`GAME-RULES.md`](GAME-RULES.md) §11.3。
- **到期错题的练习出口**：`/wrong` 只读，间隔计时到点后没有任何"来做这几道"的入口。
  做法必须是**独立练习流**（不计分、不进 `buildDailySet`、不影响全网同题与影子口径），
  否则直接破坏每日挑战的无状态红线（见 [`../AGENTS.md`](../AGENTS.md) §2.1）。
  现状已如实写进 [`GAME-RULES.md`](GAME-RULES.md) §6.1，界面文案也已同步降级为"计时/排队"。

**P2 · 内容与运营，不做不影响正确性**

- **待审池运营化**：AI 题目前只活在一句 `status: "pending"` 的响应里，服务端不落盘 ——
  需要审核界面 + 入库流水线，否则这条管线只能靠人手工搬。
- **题库深度**：每域 40 → 60 题，把单域重复率压下去（引擎已兜底"允许重复"而非空面，所以是质量问题不是故障）。
  配套工作量在内容侧，不在代码侧。

**P3 · 锦上添花，随时可推**

- **影子分身谱系**：影子从"最好的那次"扩到"最近 7 次的轨迹"曲线。

**待裁决（先别写代码）**

- **2v2 / 多人模式**：`ROOM_LIMITS.MAX_PLAYERS` 已参数化，但没有撮合与房间容量的真实需求来源。
  建议等 duel 的战绩口径（P1）解决后再谈，否则多打的两局照样不留档。
  > 排行榜已于 2026-10-20 裁定**不做**，理由见 §11.1 —— 不要再把它写回待做清单。
- **标题字号两档**：首页 `text-2xl`、其余四个页面 `text-xl`。要么统一到一档，
  要么把"首页更大"写成有意的层级差异。已记在 [`design/ui-system.md`](design/ui-system.md) §2.3。

## 1. 调研说明

### 1.1 调研对象与前提

《通识局》是一个 12 域通识知识闯关产品，三条产品线：

| 线 | 形态 | 架构约束 |
|---|---|---|
| 每日挑战 | 每天 5 题，选 1–3 个知识领域 | 题集 = `f(daySeed, domains, count)` **纯函数**，客户端与服务端跑同一份代码 → **全网同题**、**完全无状态**、可上 Serverless |
| 好友同步抢答 duel | 2 人，同一道题同一倒计时 | **服务端权威**判分（计时/判定/推进/胜负），SSE 推送 |
| 错题本 | 间隔重复，答错的题在 1/3/7/15/30 天后回流 | 本地优先 |

三条硬约束贯穿全文：**① 12 域通识；② 每日挑战必须无状态；③ 服务端权威的实时对战。**

任何外部借鉴都必须先过这三条，否则一律不采纳。

### 1.2 方法

- 全部结论基于 **web_search / web_fetch 真实检索**，不使用记忆编造；检索不到或来源相互矛盾且无法交叉验证的，标注「**未能验证**」。
- 仓库数据（star 数、最后提交时间、许可证、README）通过 **GitHub REST API** 拉取实时快照，检索日期 2026-10-20。
- 竞品拆解优先采用**一手来源**（官方帮助页、开发者访谈、百科条目、App Store 页面、仓库 README），二手测评文章仅用于补充并交叉验证。
- 视觉/文案建议需与项目已有的 `docs/design/ui-system.md`（活文档）不冲突：本文是**补充与证据**，不是替换。

### 1.3 检索关键词

英文：`NYT Mini Crossword streak leaderboard`、`Wordle share grid animation design`、`Duolingo streak freeze retention`、`Kahoot Quizizz leaderboard live quiz UX`、`QuizUp 1v1 real-time trivia scoring`、`GitHub contribution graph heatmap streak`、`open source quiz game wechat miniprogram websocket`、`daily trivia game seed date deterministic`

中文：`每日答题 开源 微信小程序`、`知识问答 GitHub stars`、`百万英雄 冲顶大会 复活卡 答题规则`、`头脑王者 段位 排位赛`、`Gitee 答题小程序 题库`

### 1.4 一句话结论

> **Wordle 的传播结构（零服务器、纯文本、全网同题）与 QuizUp 的重运营结构（匹配、榜单、赛季）在同一个赛道里走出了完全相反的结局。** 本项目应该抄前者，不抄后者。

## 2. 竞品 UI 拆解

### 2.1 NYT Mini Crossword —— 「克制的仪式感」

| 维度 | 拆解 |
|---|---|
| **视觉基调** | 纯白纸面 + 极少量墨色，**零阴影、零圆角化装饰**。信息密度高但用「格线」而非「卡片」组织。唯一彩色是完成后的蓝星。**没有任何渐变或发光。** |
| **节奏与动效** | 极慢的解题节奏，反馈只在**完成瞬间**爆发一次：官方说明为「solve the puzzle correctly, music will play and a congratulatory message will appear」——**音乐 + 一条祝贺消息**，而不是每格撒花。这与 Kahoot 的「每题都炸」是两条路。 |
| **进度 / 连胜 / 成就** | ⚠️ **官方明确写了没有连胜**：「The Mini Crossword does not have a streak feature」。进度靠：① 完成时一枚蓝星；② 计时器（可开关、可暂停、离开页面自动暂停）；③ **每日自动重置的私人排行榜**（最多 100 人，且只能是你主动邀请并确认添加的人），**明确说明不做全球榜**，理由是「无法监控作弊」。 |
| **文案风格** | 极功能化。`Clear` / `Reveal` / `Check` / `Autocheck` / `Pen mode` / `Pencil mode`。没有鼓励语，没有感叹号。 |
| **细节** | 铅笔模式（灰字=不确定，黑字=确定，蓝色=已 Check 确认）——**用字色承载「信心程度」**，这是个被低估的设计。 |

**来源**
- https://help.nytimes.com/hc/en-us/articles/360025912452 （官方帮助页：完成表现、无连胜、排行榜每日重置、仅私人榜、铅笔模式、字母颜色、检查/揭示/清空）
- https://www.boredpanda.com/nyt-mini-crossword-answers-and-hints-20-January-2026/ （佐证：solve time + 好友榜、无 Wordle 式连胜）

**对本项目的启示**
1. **每日同题 ≠ 必须做连胜。** 全网同题本身就能撑起"今天来过一次"的理由。做成「连胜」还是「期数」是一个可以晚点的决定。
2. 私人排行榜（只含你邀请的人）比全球榜更省事也更安全 —— 这与本项目 duel 的「只允许邀请 + 凭证纪律」方向一致。
3. 「铅笔模式」式的**信心度分层**可以低成本移植到每日挑战：让玩家在答对后补一句「确信 / 蒙的」，据此校准难度与解析重点。

### 2.2 Wordle —— 「零成本传播结构」

| 维度 | 拆解 |
|---|---|
| **视觉基调** | 绿 / 黄 / 灰三色方块是**唯一**的视觉语言，网格即 UI。信息密度极低但每一格都在说话。 |
| **节奏与动效** | 提交后 **逐格翻牌，从左到右，每格延迟约 100–150ms**，形成级联。反馈是「揭示」而非「庆祝」——**动效本身就是信息**（翻到一半就知道对不对）。 |
| **进度 / 连胜 / 成就** | 进度 = 6 行网格本身（一眼看到自己用了几行）；连胜 = 统计页；成就 = 分享网格。**没有一个独立的长条进度条。** |
| **文案风格** | 分享文本格式 `Wordle 210 4/6` + 表情方块，**内容本身就是文案**。按钮克制。 |
| **关键取舍** | 一天一题、**没有无限模式**、不需要 App、不需要注册、没有广告。分享时把字母抹掉只留色块 —— **"bragging without bragging"**。 |
| **硬模式（Hard Mode）** | 附加分 +50，但**藏掉 Check / Reveal 按钮**，让你没法安全网兜底。 |

**来源**
- https://wordplayforever.com/history （分享网格的传播机制、2021-11-01 90 人 → 2022 年初 30 万 → 数周后 200 万+/日、NYT 收购、归档变付费）
- https://www.playwordwar.com/history-of-wordle.html （一天一题的稀缺性、无 App、无广告、分享网格起源）
- https://eathealthy365.com/design-tips-to-make-your-own-wordle （三态反馈、逐格级联翻牌 100–150ms、Hard Mode 隐藏兜底按钮）

**对本项目的启示**
1. **分享物必须是"低信息泄露 + 高信息量"的格子**，而不是一张海报。本项目已有 `ShareCard` Canvas 骨架，缺的是**同题同格**的结构：5 格 = 5 题，每格一色（对=成功色 / 错=危险色 / 跳过=暗色）。
2. **抹掉答案、只留结果** = 不剧透但有炫耀价值。这是分享的黄金结构。
3. 每天一题的稀缺性必须**在产品层锁死**，不是运营约定。本项目的 `buildDailySet` 已经是纯函数，天然满足。

### 2.3 Duolingo —— 「连胜的工程化」

| 维度 | 拆解 |
|---|---|
| **视觉基调** | 明亮、饱和、圆润（大圆角 + 厚描边 + 拟物化 3D 按钮）。与本项目深色极简完全相反，**不建议照搬**。 |
| **节奏与动效** | 每题交互短、反馈即时、成功有音效 + 弹跳。是「消费级 App」而非「仪式」的路子。 |
| **进度 / 连胜 / 成就** | 连胜是**整个产品的经济中心**。关键设计不是数字本身，而是**失败恢复级联**：有 freeze 就消耗 freeze 保住连胜 → 没有 freeze 就用宝石修复 → 两者都没有才归零。里程碑（7/30/100 天）反过来**赠送** freeze 与宝石，形成循环。 |
| **文案风格** | 极热情、带催促（"Duolingo is sad" 之类）。**这一点本项目明确不要抄。** |
| **数据** | 连续 7 天streak 的用户完成课程的可能性高 **3.6 倍**；7 天以上 streak 的用户次日回访概率高 **2.4 倍**；streak wager 实验使 14 日留存 **+14%**；四年 600+ 次实验。 |
| **心理学底色** | 损失厌恶：**同等量级的损失，心理痛苦约为收益快感的两倍**（Kahneman & Tversky, 1979 前景理论）。所以 streak 数字的作用不是"累积胜利"，而是"**十二天的潜在损失**"。 |

**来源**
- https://www.sreedesigns.com/play/duolingo-streak （streak 机器建模：freeze → 宝石修复 → 归零的恢复级联；里程碑回馈）
- https://uxmag.com/?p=20707 （3.6 倍 / 2.4 倍 / +14% / 600 次实验；"without shame" 的伦理streak 设计）
- https://www.codexical.com/posts/2026-06-21-streak-mechanics-loss-aversion-design （streak wager 才是主因而非习惯养成；损失厌恶 ×2；2025 年 DAU 约 4770 万）
- https://mwm.ai/pt/glossary/daily-streak

**对本项目的启示**
1. **连胜的"防断签"设计比连胜本身更重要。** 本项目若上连胜，应先想清楚"断签了怎么办"。
2. **里程碑要稀疏。** 线性每 N 天弹一次会疲劳；应选 3 / 7 / 14 / 30 / 60 / 100 这种**对数式阶梯**（见 2.6 头脑王者与 2.8 节）。3 天那一次尤其关键——它足够早，低活跃用户也看得到。
3. **别抄文案。** Duolingo 式的催促是负资产；本项目要的是"陈述事实"的鼓励（见 §6）。

### 2.4 Kahoot / Quizizz（现 Wayground）—— 「主持节奏的两种答案」

| 维度 | Kahoot | Quizizz / Wayground |
|---|---|---|
| **视觉基调** | 每个题目/答案一个**饱和色块**（红蓝黄绿），大字号，投影友好；配背景音乐 | 同一套色块语言，但更"学生个人设备" |
| **节奏与动效** | 主持人控节奏，**每题后必出排行榜**；音效 + 倒计时条制造紧张 | 自定进度，答完立即反馈；可**隐藏排行榜** |
| **进度 / 成就** | 游戏 PIN → 大厅 → 逐题 → 每题榜 + 最终总榜 | 作业模式（homework）原生内置，可复查错题；报告**按题拆解** |
| **文案风格** | 主持人口吻，指令式（"Start Quiz" / "Next Question" / "Skip" / "End Quiz"） | 更像学习工具 |
| **共同结论** | 两边都强调"**分值来自速度 + 正确率**"；两边都强调"**避免刁钻题与歧义题**"；Kahoot 官方建议每题 30 秒内可答、10–15 题为佳、超过 20 题会疲劳 | |
| **无障碍** | 官方把"字号过小 / 颜色对比度不足 / 纯音频无字幕 / 动效过多"列为常见错误 —— **颜色不能是唯一线索** | 支持 TTS、音频作答 |

**来源**
- https://dominetec.com.br/en/kahoot-quiz-guide （Kahoot 官方流程与题型；10–15 题、30 秒可答、避免 trick question、常见错误里的无障碍清单）
- https://nibble-app.com/blog/kahoot-vs-quizizz （Kahoot vs Quizizz：直播 vs 自定节奏、排行榜默认可见 vs 可隐藏、homework mode、报告粒度、Quizizz 更名 Wayground）
- https://deepwiki.com/adrianboratyn/kahoot-js/3.2-host-interface （kahoot-js 开源复刻的**状态机细节**：lobby → 5 秒预览倒计时 → 题目 → 单题结果 → 累计榜，共 5 个互斥屏幕状态；单题榜与累计榜是**两份独立数据源**）

**对本项目的启示**
1. **单题榜与总榜分离**是实时对战的基本结构。本项目 duel 应在每题后给一个「本回合比分」，而不是只在最后给总比分。
2. **"跳过本题"按钮**在实时对战里是刚需（题有争议时）。当前 duel 若无此题，需要补。
3. 颜色不能是唯一线索 —— 本项目 `ui-system.md` 已经写了「颜色 + 图标 + 文案」三重线索，**这条要保住**。

### 2.5 QuizUp / Elo.World —— 「1v1 实时抢答」的原型与教训

| 维度 | QuizUp（2013–2021，已关服） | Elo.World（2025 后的接班者） |
|---|---|---|
| **赛制** | 7 轮 = 6 常规 + 1 加倍轮；每题 10 秒、4 选 1；基础 20 分，**每过 1 秒扣 1 分**；加倍轮最高 40 分；单场上限 160；平局以加倍轮分出 | 同样 1v1、同样计时、同样同题，约 90 秒一场 |
| **反馈** | 提交后**立即**绿/红高亮 + 动画，不打断节奏 | 同上 |
| **进度 / 成就** | 话题维度积分榜、国别/城市/好友榜、**54 枚勋章**、XP + 等级（只升不降）；后期加 "Echelons" 分级 | **Elo 双向评分**（每题对错都掉分或涨分），4 个榜单（世界/国家/好友/同事），**每周联赛**自动重置重开 |
| **异步** | 支持「异步挑战」：打完我这一轮，等对方有空再打 | — |
| **文案风格** | 极短：`Play Now` / `Challenge` | 同样短，FAQ 语气 |

**来源**
- http://grokipedia.com/page/QuizUp （7 轮赛制、10 秒、20 分起扣、加倍轮、Echelons、异步挑战、勋章、关服时间线）
- https://thenextweb.com/apps/2014/03/06/quizup-arrives-android/ （`Play Now` / `Challenge` 双入口、10 秒、40 话题 20 万题、城市/州/国家分榜）
- https://baike.baidu.com/item/QuizUp/12622309 （中文侧：7 轮、10 秒、首秒 200 分制、加倍题、按领域排名、54 枚勋章、聊天与讨论区）
- https://elo.world/quizup-alternative （Elo.World 对比表：QuizUp 的 XP 只升不降 vs Elo 双向；4 榜；周联赛；20 题后解锁评分；"没有广告打断答题"）

**对本项目的启示**
1. **分值要按剩余时间衰减**——这是"抢答"和"答题"的分水岭。本项目 duel 目前是"答对得分"，缺一档速度权重。
2. **加倍轮/绝杀机制**是廉价但极强的戏剧性来源（见 2.6）。
3. ⚠️ **最重的教训**：QuizUp 累计 **8000 万注册用户、日均 40 分钟、10 亿+ 对局**，仍因变现失败于 2021-03 关服。**高参与度 ≠ 可持续。** 而 Elo.World 改用 **Elo 双向评分 + 周联赛**（每题对错都影响分数）替代"只升不降的 XP"——**说明"和过去的自己比"比"和排行榜比"更能撑住长期留存，且成本低得多。**
4. 这条直接支持本项目已有的**「影子对手」**机制（与过去自己比），而且 Elo.World 给出了更强的理论支撑：**分数应当可降**，否则它只是"玩了多少小时"的度量。

### 2.6 头脑王者 / 知乎答题王 —— 「中文赛制的完整样本」

| 维度 | 拆解 |
|---|---|
| **赛制** | 每局 5 题、2 人；对手是**此刻同样在玩的人**、**镜像玩家**或**机器人**（高段位场缺人时）；每题 10 秒，**不用道具时答对最高 200 分，每过 1 秒递减 20 分**（第 1 秒 200 / 剩 9 秒 180 / 剩 8 秒 160…）；**最后一题分值翻倍**（400/380/…），理论单场满分 1200；最后一题反超显示「**绝杀**」 |
| **段位** | **14 段**：入门新手 → 起步熟手 → 坚韧黑铁 → 顽强青铜 → 傲气白银 → 聪慧黄金 → 巧思白金 → 睿智黑金 → 无暇钻石 → 智者大师 → 万卷宗师 → 博学史诗 → 智慧传说 → **头脑王者**。赢加星、输扣星，段位越高门槛星数越多 |
| **社交** | 好友对战 + **观战**（只有被邀请才能观战，自己不能主动观战）；对战结束后可把成绩发到两人都在的群里做排位展示；转发出去的是**转发者自己的成绩页**，被转发者打开后还能再转发 —— 二级裂变 |
| **成长** | 「**知识升级**」：用技能书 + 王者币提升某一学科等级（语文/历史/数理化技能树），科目等级高则遇到相关题不吃亏 |
| **UGC** | 「**题目工厂**」：玩家自己出题，等系统与其他玩家审核，通过后进题库 |
| **经济** | 王者币是进场费，段位越高入场费越贵；每 3 小时自动生成 60 币，需定时去领（断签惩罚） |
| **⚠️ 合规** | 2018-01-31 因**部分题目涉政**违反《即时通信工具公众信息服务管理规定》被暂停服务；2018-02-17 重新上线并改名「**知乎答题王**」 |

**来源**
- https://mzh.moegirl.org.cn/头脑王者 （萌娘百科：赛制、14 段位、商店/银行/知识升级/好友对战/观战/题目工厂、涉政下架与改名）

### 2.7 百万英雄 / 冲顶大会 —— 「直播答题的分享与复活」

| 维度 | 拆解 |
|---|---|
| **赛制** | 每场 12 道选择题，**每题 10 秒**，答错或超时即淘汰；全部答对者瓜分当期奖金池（5 万–100 万不等） |
| **防挫败** | **复活卡**：每位用户有专属邀请码，好友首次填写后**双方各得一张**；答错时自动生效，**每场限用 1 张** |
| **节奏** | 场次固定（每天 4 场：13:00 / 15:00 / 20:00 / 21:00），每场约 15 分钟，**强仪式感 + 强稀缺性** |
| **文案风格** | 极短、极物质：「复活卡」「冲顶成功」「瓜分百万奖金」「距离现金大奖更近一步」 |
| **对比** | 《冲顶大会》题目更难 → 走到最后的只有少数人 → 奖金被少数人分走；《百万英雄》题目更简单 → 更多人能进入瓜分池。**结果玩家从冲顶大会迁移到百万英雄。** |

**对本项目的启示**
1. **「复活」是分享的动机，不是惩罚**。分享给朋友 → **双方**都受益（邀请码机制）。本项目做分享图时应体现"被分享者也能拿到东西"，而不是纯炫耀。
2. **题目难度决定参与广度**。太难 → 只有少数人玩得下去 → 分享圈层收窄。12 域通识的产品定位天然是"广度"，这与《百万英雄》的教训一致：**别让某几域把大部分人卡在门外**（本项目 12 域里 6 域还没有题库，题库缺口会让"选域"变成运气游戏）。
3. **固定场次 + 强稀缺**是"每天回来"的最短路径。本项目每日挑战是"全天可玩"，需要用别的机制补偿稀缺感（→ 分享图上的日期/编号，见 §4）。

## 4. 差异化机制候选

### 4.1 先对齐：本项目**已经实现**的 3 个机制

| 机制 | 一句话 | 成本 | 无状态兼容 | 说明 |
|---|---|---|---|---|
| **影子对手** | 与「同领域组合下的历史最好成绩」同场竞速 | 低 | ✅ 完全兼容（本地历史数据） | 已被 §2.5 的 Elo.World 案例佐证为有效方向 |
| **通识段位** | 见习→入门→通识→博闻→渊博→睿哲 六段阶梯，由本地生涯累计算出 | 低 | ✅ 本地生涯数据 | 对标头脑王者 14 段位，但**更短**（6 段），更适合"每天 5 题"的低频场景 |
| **盲盒轮转** | 1 个本命领域 + 2 个由日期种子决定的每日盲盒领域，强制跨域 | 低 | ✅ 纯函数 | 直接服务于「跨域连击」的正向激励 |

### 4.2 候选机制（8 个）

### 4.4 推荐前 3（可并行推进，互不冲突）

**Top 1 —— A. 12 域分色热力图「知识足迹」**
放 `/history` 或 `/map`，用本地生涯数据渲染。成本 ≈ 一个纯 CSS 网格组件 + 一次本地数据聚合，**不动任何服务端、不动任何题库**。它把本项目目前最弱的一环（"打完就散"）变成**一张会累积的个人资产**。热力图是 GitHub 用十几年教给用户的视觉语言，不需要教育成本。

**Top 2 —— C. 离线「同题 PK 码」**
这是**只有本项目能做**的机制。所有竞品要做同样的事必须上服务器（撮合、存题、比对成绩），我们只要一个**短码 + 同一份日期种子**。落地时注意：短码应编码 `dateKey + 领域组合的 canonical hash`，对方的客户端据此重建题集，**成绩比对走本地交换（Paste 码 / 截图）也可以**，第一版甚至可以完全不做服务器。

**Top 3 —— B. 每日一题「认证卡」+ 同题方块网格**
在现有 `ShareCard` 上改造：格子化 + 域色 + 日期 + 题号 + 用时 + 连击。低成本、高传播。**关键取舍**：只给结果不给答案（Wordle 原则），并且**被分享者能拿到东西**（百万英雄复活卡原则）——例如"对方用你的码 PK 时，你的卡片上会多一枚'被挑战'标记"。

> **建议顺序**：B（先有传播） → A（先有资产） → C（最后放大优势）。三者都**不需要服务端改动**，与「每日挑战无状态」红线完全兼容。

> 落点：`tailwind.config.ts` + `app/globals.css`。

### 5.1 配色（语义 token 清单）

| Token | 值 | 语义角色 | 为什么需要 |

| `surface` | `#141826` | 卡片面 | 已有 |
| `surface-2` | `#1C2132` | 内嵌面 / secondary 按钮 | 已有 |
| `accent` | `#FF6A2B` | **品牌**：主 CTA、分数、连击 | 已有。⚠️ 红线：**accent 不做"今天是什么颜色"** —— 那是域色的活 |
| `success` | `#34D399` | 答对 / 打卡完成 | 已有 |
| `danger` | `#FB7185` | 答错 / 超时 / 断签 | 已有 |
| `gold` | `#FFC24B` | 星级、里程碑、连胜、**护盾/免答** | 已有 |
| `info` | `#5FA8FF` | 中性提示、**对手侧** | 已有 |
| **`stale`** 🆕 | `#3A4363` | **断签 / 未达成的目标格**（热力图空档、对战中的"未出手"） | 调研发现：现有 token 里**没有"灰色的失败"**。热力图的空格必须和"深色但有进度"区分开，否则用户分不清"没打"和"打了但低分" |

| **`combo`** 🆕 | `linear-gradient(90deg, #FF6A2B, #FFC24B)` | **连击的专用渐变** | 跨域连击是核心正向激励，**它不该和静态 accent 长得一样**。用橙→金渐变只有"热度上升"时出现，静态元素永不触发 |

**12 域主题色**（`content/domains/index.ts` 现有值，**不改**）：

`gaming #6C5CE7` · `anime #FF6B9D` · `tech #00B894` · `coding #0984E3` · `life #E17055` · `history #A29BFE` · `auto #D63031` · `mobile #00CEC9` · `film #E84393` · `science #00A8B5` · `literature #8E44AD` · `travel #F39C12`

> ⚠️ **域色 vs accent 的分工红线**（沿用 `ui-system.md` §2.1 并强化）：
> **域色 = 上下文身份**（4px 色条 / 胶囊 / 微光 / 分享卡顶条），**永不**做大面积底色；
> **accent = 品牌与 CTA**（按钮、分数、连击），**永不**表示"今天选了哪个域"。
> 二者同时出现在一屏时，**域色面积必须小于 accent 面积的 1/4**。

### 5.2 字体栈

不引新依赖（项目红线），沿用系统栈：

```css
--font-sans: ui-sans-serif, system-ui, "PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif;
/* 🆕 等宽栈：仅用于倒计时 / 用时 / 分数 / 题号 */
--font-mono: ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas, "Liberation Mono", monospace;
```

- **数字一律 `font-variant-numeric: tabular-nums`** —— 倒计时与分数**不许跳字**（已有，保留）。
- 建议把**倒计时 / 用时 / 题号 / 分数**切到 `--font-mono`：等宽数字让"3 → 2 → 1"的宽度不变，视觉上不跳动。中文题干仍走 `--font-sans`。
- 字号层级沿用 `ui-system.md` §2.3（Display 32 / Title 20 / Question 18/1.7 / Body 15/1.65 / Label 13 / Caption 12），**不新增字号**。
- 中文正文**不加字距**（会散）；仅标题 `letter-spacing: -0.01em`。

### 5.3 圆角与阴影层级

沿用 `ui-system.md` §2.4（`r-sm 10` / `r-md 14` / `r-lg 20` / `r-pill 999` + `shadow-card` / `shadow-glow` / `shadow-pop`），补一条**层级规则**：

```
页面底(无边框) < 卡片(细边+阴影) < 内嵌面(surface-2) < 悬浮/强调(发光边) < 结算页(顶部 8px 域色渐变条)
```

**结算页顶条**是唯一允许使用"大块域色"的位置（≤ 8px 宽），因为它不承载文字，不影响可读性。

### 5.4 关键动效

| 场景 | 动效 | 时长 / 曲线 | 说明 |
|---|---|---|---|
| **答对** | 选中项 `scale(0.96) → 1` + 边框转 `success` + 底色 8%→15% | 320ms `cubic-bezier(.34,1.56,.64,1)` | 弹到位即停，不循环 |
| **答错** | `shake` 关键帧 ±4px | 280ms `ease-out` | 只震**被选中的那一个选项**，不震整张卡 |
| **揭示答案** | 正确项边框 0→2px `success` + 底色 0→8% | 400ms `ease-out` | 与解析面板滑入**错开 80ms**，制造"先给答案、再给理由"的顺序感 |
| **解析面板** | `translateY(8px) → 0` + 淡入 | 220ms `cubic-bezier(.22,1,.36,1)` | 滑入而非展开，视觉重量小 |
| **连击跳动** | 连击数 `scale(1) → 1.08 → 1`，同时 `combo` 渐变描边由 30% → 100% | 260ms `cubic-bezier(.34,1.56,.64,1)` | 每次连击 +1 触发一次；**答错不触发**（连击归零时也不播反向动效，用变暗代替） |
| **时间条** | `transform: scaleX()` | 线性，绑定剩余时间 | ⚠️ **禁止动 width/height**（会引发布局抖动） |
| **结算入场** | 分数 `scale(0.9)→1` + 数字滚动 | 280ms | 只在结算页，答题页禁止 |

**硬规则**（沿用 `ui-system.md` §2.5）：**答题时一屏最多 2 个关键动效**（选项反馈 + 进度变化），其余静止；任何状态切换都不得 0ms 突变；`prefers-reduced-motion: reduce` 时全部归零。

### 5.5 三个"眼前一亮"但克制的视觉小技巧

**① 域色"点亮"（成本极低，识别度极高）**
选项左侧 4px 域色条平时是 18% 不透明；**答对时该条在 200ms 内升到 100% 并向右延展 2px**。答错时它只是**变暗到 8%**（"这条你没点亮"）。用户不需要读文字就知道这题属于哪个域、自己有没有点亮它 —— 一条 4px 的竖线完成了全部叙事。

**② "题号圆点"进度条（替代线性进度条）**
顶部 5 个小圆点代替进度条：当前题 = `accent` 空心环（带轻微呼吸）、已答对 = `success` 实心、已答错 = `danger` 空心环 + 45% 透明、未到达 = `surface-3` 填充。**一屏看完"今天答成什么样了"**，比线性条的信息密度高一个量级，且在窄屏上不占宽度。

**③ 倒计时的"呼吸"而不是"闪烁"**
剩余 ≤ 5s 时，数字转 `danger` **并加 1.2s 循环的 4% 缩放脉冲**（`scale(1) → 1.04`），**不闪烁、不变色闪烁**。闪烁会引发前庭不适（`ui-system.md` 已把无障碍列为红线），而"呼吸"传达的是"时间在流逝"而非"警报在闪"。

> ❌ **明确不要做的**：彩带 / 彩纸 / 满屏粒子 / 连续弹跳 / emoji 满屏。理由很直接 —— 这些在答题页会**遮挡选项文本**，且与"克制、有品味"的产品调性冲突（参考 §2.1 NYT Mini：完成时才响一次音乐）。

## 6. 文案规范建议

**语气定位**：像一个**有点幽默但不吵的 Trivia 主持人**。
- 句子 ≤ 20 字；不用「！」连发；不用「哦 / 啊 / 呀 / 呢」
- **只陈述事实，不评价用户聪明与否**（不说"你真聪明"，说"比上次快 4 秒"）
- 鼓励必须**具体**：说清楚"你比什么强了多少"
- 数字用 `tabular-nums` 呈现时，文案里的数字与 UI 数字必须一致

## 8. 调研过程中发现的、最需要产品决策的三件事

1. **合规缺口（最高优先级）**：头脑王者 2018 年因**题目涉政**被暂停服务、改名「知乎答题王」才重新上线。本项目「历史·文化」域的人工题库**不经过** `lib/ai/validate.ts` 的敏感词校验链 —— 这是本次调研发现的**最硬的风险**，建议单独立项补齐（不影响本次 UI 改造，但优先级高于任何新机制）。
2. **连胜要不要做**：NYT Mini **官方明示不做连胜**（每日同题本身就够），Duolingo 靠连胜做成数亿美元生意。本项目当前**没有任何连胜机制**，但已有「影子对手 + 通识段位」两个替代性留存锚点。建议**先不上连胜**，把预算投在 A（热力图）和 C（同题 PK 码）上 —— 它们同样制造"明天还要来"的理由，但**不会制造"断了就全没了"的焦虑**。
3. **不要抄 QuizUp 的结构**：8000 万注册、日均 40 分钟、10 亿+ 对局，仍于 2021 年关服。**重运营的匹配 / 榜单 / 赛季结构，对一个无账号体系的独立产品是负资产。** 本项目应该抄 Wordle 的**传播结构**（零服务端、纯文本、全网同题），这是我们唯一的结构性优势。

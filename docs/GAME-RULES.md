## 1. 日期与种子

### 1.1 日期口径

```
dateKey = "YYYY-MM-DD"   // 时区固定为 Asia/Shanghai
```

- **不是 UTC**。跨零点自动换题。
- 修改时区口径会改变所有人的当日题目 —— **慎改**。

实现：`lib/engine/date.ts`

### 1.2 每日挑战种子

```
daySeed = hashSeed("daily:" + dateKey + ":" + canonicalDomains(domains).join(","))
```

`canonicalDomains()` = **排序后的副本**。领域是**集合**，不是列表：

> 用户 A 先点游戏再点动漫、用户 B 先点动漫再点游戏 —— 选的是同一组领域，
> 当天拿到的题**完全相同**。这是「全网同题」的前提，**不要把排序去掉**。

实现：`lib/engine/daily.ts` · `canonicalDomains()` / `dailySeed()`

### 1.3 盲盒种子

```
blindboxSeed = hashSeed("blindbox:" + dateKey)
```

盲盒领域**与用户无关** —— 同一天、同一候选池 → 同一批盲盒领域。

## 2. 每日挑战

### 2.1 抽题算法

1. `daySeed` 初始化 PRNG（`mulberry32`）；
2. 领域轮转顺序 = 对**可用**领域做 Fisher-Yates 洗牌；
3. 第 `i` 题取自 `order[i % order.length]`；
4. 域内按 PRNG 取**未出过的**题，优先匹配难度曲线，不足则放宽；
5. **末位为「彩蛋题」**：取自与上一题**不同**的领域（仍在所选领域内）。

**难度曲线**（5 题时为 `1,1,2,2,3`）：

```
difficultyCurve(n)[i] = DIFFICULTY_CURVE[min(len-1, floor(i * 5 / n))]
```

**退化行为**（保证绝不出现空题面）：

| 情况 | 处理 |
|---|---|
| 某域没有匹配难度的题 | 放宽到该域任意难度 |
| 某域已出完 | 允许重复（题量不足时的兜底） |
| 某域完全为空 | 跳过该域，用其他域补位 |
| 全部为空 | 返回空数组，由调用方提示「题库准备中」 |

### 2.2 三种领域模式

| 模式 | 领域来源 | 档案是否写回 |
|---|---|---|
| `native` 本命模式 | 玩家选定的 1–3 个 | ✅ 写回 |
| `blindbox` 盲盒轮转 | 本命第 1 个 + 当日盲盒 2 个 | ✅ 只写回本命 |
| `random` 随缘开局 | 按日期种子取 3 个 | ❌ **不写回** |

> ⚠️ `random` 模式**绝不能**把随机结果写回档案 —— 写回会导致第二天起不再轮换，
> 「随缘」会退化成固定领域。这正是修掉的一个老 bug。

实现：`lib/engine/blindbox.ts` · `resolveDailyDomains()`

### 2.3 每日挑战的锁定

- 当日题集一旦抽出即**锁定**（存 `DailySession.questionIds`），当天改领域**不重算**；
- 改领域只对**次日**生效；
- 重新进入页面时以 `DailySession.domains` 为准，不用当前档案覆盖。

## 3. 计分

### 3.1 公式

```
base   = { 难度1: 10, 难度2: 20, 难度3: 30 }
speed  = clamp(1 - elapsed / limit, 0, 1) * 0.5 + 0.5     // 0.5 ~ 1.0
blitz  = elapsed <= limit / 3 ? 1.2 : 1.0                  // 秒答加成
points = round(base * speed * blitz * comboMultiplier)
```

- `elapsed` = 实际作答用时（毫秒），**服务端权威**（duel）或客户端本地计（daily，无排行榜可刷）；
- `limit` = 限时，随难度递减。

### 3.2 限时

| 难度 | 限时 |
|---|---|
| 1 | 30s |
| 2 | 25s |
| 3 | 20s |

**唯一入口**：`lib/engine/scoring.ts` 的 `DIFFICULTY_LIMIT_MS`。
服务端状态机（`lib/store/room.ts`）与 `hooks/useDailyChallenge` / `hooks/usePkChallenge` /
`app/daily` / `app/pk` 全部 import 它 —— **不要**在客户端再抄一份数字表，
否则改限时只会改到一半。

### 3.3 星级

```
ratio = score / maxScore(difficulties)
ratio ≥ 0.60 → ★★★
ratio ≥ 0.35 → ★★
否则        → ★
```

`maxScore` = 各难度 `base × 1.0 × 1.2 × 1.2` 之和（速度满、秒答加成、连击封顶同时取到）。

### 3.4 跨域连击（纯正向激励）

| 情况 | 连击变化 |
|---|---|
| 跨域抢先答对 | **+1** |
| 同域抢先答对 | 不变（不奖不罚） |
| 答错 | **归零** |
| 超时未答 | **归零** |
| **对手抢先答对** | **不变**（这不算你失误） |

> 最后一条解掉了早期方案里「对手答对 = 你失误」与「连击只增不减」两条规则的冲突。

### 3.5 连击倍率

```
combo ≥ 6 → ×1.2
combo ≥ 4 → ×1.1
combo ≥ 2 → ×1.05
否则      → ×1.0
```

封顶 ×1.2，避免滚雪球。

### 3.6 胜负判定

```
先比总分；平分则比「抢先答对次数」；再平则平局
```

实现：`lib/engine/scoring.ts` · `decideWinner()`

## 4. 影子对手

### 4.1 归属

按**领域集合的规范序**分组（`ghostKey()` = 排序后用 `+` 连接）。
选同一组领域才是同一个对手；领域集合不同 → 影子互不干扰。

### 4.2 记录内容

| 字段 | 含义 |
|---|---|
| `bestScore` | 该组领域下的**历史最高总分** |
| `bestCorrect` | 达到该分数时的答对题数 |
| `bestDate` | 达到该分数的日期 |
| `plays` | 该组领域下完成的局数 |
| `bestElapsed` | 历史最佳总用时（同分时取更快的那次） |

### 4.3 更新与对比

```
delta = 本次得分 - 影子得分
```

| 条件 | 结论 | 文案 |
|---|---|---|
| 无影子 | `first` | 第一次挑战 —— 今天的成绩就是明天的影子 |
| `delta > 0` | `beat` | 超过过去的自己 N 分 |
| `delta = 0` | `tied` | 追平了自己的影子 |
| `delta < 0` 且 `\|delta\| ≤ 影子分 × 10%` | `near` | 差 N 分就追平影子 |
| 其他 | `behind` | 落后影子 N 分 |

> **顺序铁律**：先用**本局开始前**的影子算结论，**再**更新影子。
> 反过来就是自己跟自己比，结论永远没意义。

> 「差一点」阈值 = 影子分 × 10%，且**至少 1 分**（影子分很低时不会因为 0.5 分就说"差一点"）。

实现：`lib/engine/ghost.ts`

## 5. 通识段位

### 5.1 通识值

```
通识值 = 答对题数×3 + 完成局数×4 + 星级总数×6 + 触及知识点数×2 + 最高连击×5 + 最长连续天数×2
```

### 5.2 段位阶梯

| 段位 | 门槛 | 描述 |
|---|---|---|
| 见习 | 0 | 刚进门，路还没认熟 |
| 入门 | 150 | 开始上道了 |
| 通识 | 600 | 像个通识玩家了 |
| 博闻 | 1500 | 朋友愿意跟你聊 |
| 渊博 | 3200 | 话题覆盖半个互联网 |
| 睿哲 | 6000 | 身边人的知识百科 |

### 5.3 进度条语义

进度是**段内进度**（当前值 - 本段门槛）/ 段宽：

- 晋级瞬间**归零重来** —— 每一段都要重新爬一遍；
- 满级后 `nextThreshold = null`、`progress = 1`。

### 5.4 数据来源

**生涯累计**（`lifetime` 存储）**不受"最近 30 场"历史窗口影响**。
`getHistory()` 只保留 30 场（给战绩页看），段位必须用独立的不截断计数。

实现：`lib/engine/rank.ts` · `lib/storage.ts` · `getRankSnapshot()`

## 6. 错题本（间隔重复）

SM-2 简化版，间隔序列：

```
1 → 3 → 7 → 15 → 30 天
```

| 事件 | 变化 |
|---|---|
| 答错 | 连击归零、间隔重置到第 1 级、难度因子 `ease` 下调 |
| 答对 | 连击 +1、间隔推进到下一级 |
| **连对 2 次** | **毕业**，从错题队列移出 |

### 6.1 到期错题怎么「回来」

**每日题集仍然不包含错题队列。** `buildDailySet({ dateKey, domains, count, pool, seed })`
的入参没有错题队列 —— 当日题集只由「日期 + 领域集合」决定（红线：无状态、全网同题）。

到期错题通过**独立练习流** `/wrong/practice` 重做：

- 入口：`/wrong` 的「开始复习 N 题」，只对 `isDue()` 为真的条目开放；
- 选题：`dueEntries()` 按 `nextDueAt` 升序（同一时刻按 `questionId` 字典序），
  最多取 `PRACTICE_LIMIT = 10` 题；只从本地完整题库按 id 还原，找不到的条目跳过；
- 作答：**无倒计时**；提交后用 `isCorrect()` 判定，再调用
  `recordAttempt({ mastery: false })`，**只推进错题间隔**（答错 `onWrong` / 答对 `onCorrect`），
  连对 2 次毕业；
- 不写：分数、战绩 `history`、streak、lifetime/段位、熟练度、影子；
  也不调用 `buildDailySet`。因此不影响每日挑战的确定性、全网同题与影子口径。

> 结论：间隔序列驱动的是「这道题该怎么计时」；「到期」只决定**练习入口是否可点**，
> 不会把题塞进当日题集。

实现：`lib/engine/repetition.ts` · `lib/engine/practice.ts` · `app/wrong/practice/page.tsx`
调用方：`hooks/useDailyChallenge.ts` · `hooks/usePkChallenge.ts` · duel 结算 · 展示 `app/wrong/page.tsx`

## 8. 熟练度与星图

- 熟练度表 key = `"{domain}|{topic}"`；
- 每次作答 `correct ? +1 : -1`，**下限 0**（钳制，不会变负）；
- 星级 = `clamp(floor(value / 2), 0, 5)`；
- 「触及过的知识点数」= 熟练度表中**值非 0** 的条目数（用于段位）。

实现：`lib/storage.ts` · `recordMastery()` / `masteryStars()` / `countTopicsTouched()`

> 错题复习流（`/wrong/practice`）**不更新熟练度**（`recordAttempt({ mastery: false })`）——
> 复习只推进错题间隔，不刷星图与段位。

## 9. 答案判定

### 9.1 归一化

```
全角转半角 → 英文小写 → 去所有空白 → 去常见标点
```

（顺序即 `normalizeAnswer` / `normalizeStem` 的实现顺序：**先**转半角，
之后标点表才能同时命中全角与半角符号。）

### 9.2 判定

| 题型 | 规则 |
|---|---|
| `single` | 归一化后与正确答案相等 |
| `judge` | 同上；选项固定 `["正确", "错误"]` |
| `multi` | **集合全等**：数量相同且逐项相等（少选、多选、错选都算错） |

### 9.3 存储形态 vs 比较形态（两套顺序）

| 场景 | 顺序 |
|---|---|
| **入库存储**（`canonicalAnswer`） | 按**原始字符串**字典序排序 |
| **比较**（`normalizeAnswerList`） | 按**归一化后**排序 |

> 两套顺序必须分开 —— 归一化会去掉标点空格，**理论上会改变相对次序**。
> 用同一套顺序会在某些题上误判。

### 9.4 为什么答案存文本而不是字母

客户端可能对选项排序，`"A"` 会失效。`answer` 存**选项文本**（如 `"《幽灵公主》"`）。

实现：`lib/engine/answer.ts`

## 10. 边界情况速查

| 场景 | 处理 |
|---|---|
| 题库某域为空 | 跳过该域补位；全空则提示「题库准备中」 |
| 错题复习时题库里找不到该题 | 跳过该条，不阻塞本轮（题库变更后的兜底） |
| 题目难度不匹配 | 放宽到该域任意难度 |
| 同域题目已出完 | 允许重复（兜底） |
| 玩家在开局后加入 | 拒绝（`room_started`） |
| 玩家重复提交同一题 | 拒绝（`already_answered`） |
| 本方答错 | **回合不结束**：立即记 0 分并清零连击，对手在截止前答对照样拿走分值 |
| 提交的 `roundIndex` 过期 | 拒绝（`stale_round`） |
| 超时后才提交（duel） | **408 `timeout`**（不是 `not_answering`） |
| 超时后才提交（daily / PK） | **不禁止作答**：倒计时归零后仍可点，`elapsed` 被钳到 `limit`，速度分取最低档 0.5（无服务端可作弊面，故不做硬拒） |
| 客户端漏收 `round_start`（SSE 轮换间隙） | 回合态以快照 `roundIndex` 为准并重置本地提交态，见 [`ARCHITECTURE.md`](ARCHITECTURE.md) §4.3 |
| 对手抢先答对 | 你**没有**失误，连击保持 |
| 客户端伪造 `elapsed` | Zod 剥离该字段，无效 |
| localStorage 不可用（隐私模式） | 降级为**内存存储**，游戏仍可玩，UI 给出提示 |
| 段位输入为负（历史脏数据） | 钳制为 0，不扣段位 |

## 11. 同题 PK

### 11.1 码与规格

```
PK 码           = 4–6 位，字母表 "ABCDEFGHJKLMNPQRSTUVWXYZ23456789"（排除 I/O/0/1）
今日推荐码      = codeFromSeed(hashSeed("pk-code:" + dateKey))     // 全网同天一致
PK 种子         = hashSeed("pk:" + dateKey + ":" + normalize(code))
PK 领域         = pickDomainsBySeed(hashSeed("pk-domains:" + dateKey + ":" + normalize(code)), 池, 3)
题集            = buildDailySet({ dateKey, domains, pool, seed: PK 种子 })
```

**「同题」的全部秘密**：`buildDailySet` 本来就支持显式 seed（duel 已在用），
PK 只是把 seed 的来源换成「日期 + 码」的哈希。两个人各自本地跑一遍，得到完全相同的题。

> ⚠️ **候选池的顺序参与洗牌**。所以「扩池」（新增领域）会改变所有 PK 局的题目 —— 这是预期行为。

### 11.2 计分与连击

PK **完全复用**每日挑战的计分、连击、速度与秒答加成公式。
同分同题才可比 —— 这正是复用公式的前提。

### 11.3 与其他模式的分工

| 模式 | 对手 | 计入 streak | 计入段位 | 更新熟练度 / 错题本 | 写进战绩 history |
|---|---|---|---|---|---|
| 每日挑战 | 影子（过去的自己） | ✅ | ✅ | ✅ | ✅ |
| 同题 PK | 对方（线下对账） | ❌ | ❌ | ✅ | ❌ |
| 同步抢答 duel | 对手（实时） | ❌ | ❌ | ✅（仅本人实际作答过的回合） | ✅（`mode: "duel"` + `roomCode`） |
| 到期错题复习 | 无（独立练习） | ❌ | ❌ | 只更新错题本（不更新熟练度） | ❌ |

> PK **不计入 streak 与段位** —— 否则可以反复开 PK 刷段位。
> 但它**更新熟练度与错题本** —— 学到的东西和从别处学到的是同一批。
>
> duel 的判定与比分全部来自服务端快照（`RoundRecord.correct` / `PublicPlayer.maxCombo`），
> 客户端只负责在结束后写本地档案。**被对手抢先 / 自己未作答的回合不写**：
> 既不加熟练度，也不进错题本。`matchId = 房间码 + ":" + seed` 用于去重，
> 刷新结算页不会重复写；rematch 换 seed 后才会重新结算。
> **仍不写 streak、lifetime/段位、影子与每日 session**（防刷）。
>
> 错题复习的优先级更低：它**只推进错题间隔**，连熟练度都不写（见 §6.1）。

### 11.4 诚实的边界

| 有 | 没有 |
|---|---|
| 题目、顺序、难度完全一致 | 实时同步（不是同时开抢，是"同题、各自跑、最后比"） |
| 成绩卡带 PK 码 + 5 格方块，可逐格对账 | 自动判胜（靠成绩卡线下对照） |
| 换设备也能玩（码一样题就一样） | 换设备共享进度（无账号体系） |

实现：`lib/engine/pk.ts` · `hooks/usePkChallenge.ts` · `app/pk/page.tsx`
